# 核心定义

本文件用于防止死锁、阻塞、完成和 nonblocking 概念混淆。

## 1. 完成状态

状态：定义。

稳定状态 `s` 是完成状态，当且仅当所有 `j in J` 已到达其路线终点，且不再持有机器、缓冲、AGV 或预约 token。完成类记为 `F`。

完成是全局标识状态，不等同于“没有当前可加工任务”。

## 2. 操作死锁

状态：定义。

稳定状态 `s` 是全局操作死锁，当且仅当：

1. `s notin F`；
2. `s` 中至少一个未完成工件处于等待或阻塞；
3. 不存在任何允许系统走向不同稳定状态的 admissible successor，包括可控事件、不可控事件及其闭包后继。

若可控策略人为禁用所有事件导致停滞，该状态属于策略诱导停滞，不能直接称为系统结构操作死锁，除非所有安全许可事件也确实不可发生。

## 3. 局部死锁

状态：定义。

稳定状态 `s` 含局部死锁，当存在非空工件子集 `J' subset J`，使 `J'` 内所有未完成工件相互等待或等待由 `J'` 不可自主释放的资源，且 `J'` 内无工件能在不依赖外部释放的情况下继续。

局部死锁不必阻止其它工件完成，因此不等同全局操作死锁。

## 3a. 容量介导全局操作死锁

状态：项目内已证明（严格受限子类）。

容量介导全局操作死锁是一般全局操作死锁的子类。它要求每个被覆盖的未完成非终端阻塞工件都至少有一个 capacity-ready 直接进展替代：非容量 guard、时钟成熟、同步握手和策略选择已经满足，剩余阻塞完全来自资源容量或硬预约 token 不足。当前 enabled 的 timed/transport completion 是空需求替代，因此不能被容量核阻塞。

永久质量 guard、外部同步永不满足、未建模批准缺失、calendar-empty terminal block 或 policy stall 可以造成一般停滞或一般操作死锁边界，但不属于 P2 的容量介导死锁。

`event_calendar_empty` 是编码状态中的当前事实：此刻没有已排程且成熟或待处理的 timed/transport completion。它本身不推出 calendar-empty terminal block。calendar-empty terminal block 是一种解释分类，表示系统因为外部未来事件、调度地平线或未建模事件源缺失而停在非完成边界；P2 仍排除这种解释分类。

## 4. 准死锁

状态：定义。

稳定状态 `s` 是准死锁，当系统尚有至少一个可发生事件，但所有可发生事件都不能消除某个封闭等待结构，或只能让系统在等价阻塞类中移动。

这里的“等价阻塞类”只是发现阶段的占位概念：两个状态若保留同一组被封闭阻塞的工件、同一组不可自主释放的关键持有、并且所有合法替代后继仍被同一 core 内容量缺口阻塞，则可暂时视为等价。冻结理论前必须把该关系形式化为等价关系或删除该术语。准死锁需要额外的进展或公平性假设才能转化为概率死锁或 nonblocking 失败。

## 5. 结构可死锁

状态：定义。

模型 `I` 结构可死锁，当存在某个合法参数实例和初始条件下的可达稳定状态 `s` 为操作死锁，且死锁可由持有-请求-释放结构解释，而不是由故障、外生停止或人为禁用造成。

结构可死锁是存在性概念，不是给定速率下的概率陈述。

## 6. 概率死锁

状态：定义。

在 `IMS-CTMC` 或带随机调度的有限 DES 中，概率死锁指从初始状态先达死锁吸收类 `D` 而非完成吸收类 `F` 的概率 `P_i(tau_D < tau_F)`。

概率死锁允许结构上存在死锁但概率为零，也允许死锁概率因速率、调度或控制策略改变。

## 7. Liveness、Deadlock-Free 与 Nonblocking

状态：定义。

- `deadlock-free`：所有可达稳定非完成状态至少有一个允许后继。
- `liveness`：每个相关事件或变迁在可达演化中不会永久失活；具体版本必须指明事件集与公平性假设。
- `standard nonblocking`：每个可达状态都存在一条到 marked completion 的有限延拓。

状态：文献基线。标准 nonblocking 是存在延拓性质，不保证所有随机路径必完成，也不排除无限 livelock 本身；若要从 nonblocking 推出几乎必然完成，必须加入有限状态、正概率进展、公平调度或 CTMC 非爆炸等额外假设。

## 8. 多容量等待证书

状态：定义。

等待证书不是简单有向环。一个候选 `DeadlockCertificate` 至少包含：

- `jobs(K)`：被证书覆盖的未完成工件；
- `resources(K)`：涉及的机器、缓冲、AGV、预约 token；
- `hold` 边：每个工件实际持有和预约持有的资源量；
- `need` 边：每个工件每个可选后继所需资源及需求量；
- `W_K`：容量缺口 witness 记录 `(job, alternative, resource/token)`；
- `H_K`：holder 解释记录 `(holder job, resource/token, quantity, blocked job, alternative)`；
- `residual`：考虑 `K` 内不可自主释放持有后的残余容量；
- `blocked mode`：BAS、blocked-unload、等待运输、等待预约兑现等；
- `alternative successors`：若有替代路线、替代 AGV 或替代预约兑现路径，必须用全称量词证明所有合法替代后继均被 core 内不可用容量或不可兑现 token 阻塞；
- `non-self-release`：证明相关持有不能在不满足需求的情况下自主释放；
- `reachable prefix`：从初始状态到证书状态的最短或审计可达前缀；
- `assumptions`：证书适用的闭包、预约、容量和选择假设。

## 9. 封闭阻塞核

状态：定义；capacity-mediated 子域等价已证明，一般情形拟证明。

在稳定状态 `s` 中，`K` 是封闭阻塞核，当且仅当：

1. `jobs(K)` 非空，且每个工件未完成；
2. 对 `jobs(K)` 中每个工件的每个 capacity-ready OR-of-AND 替代需求，均至少存在一个容量缺口 witness；当前 enabled 的 timed/transport completion 是空需求替代，因此不能被封闭核阻塞；
3. 每个 witness 的缺口完全由 `H_K` 中 `K` 内工件不可自主释放的持有或硬预约解释；软预约不在已证完备定理内；
4. 每个用于解释缺口的 holder，在成功 acquire/unload/handoff/leave 或语义指定 completion-release 前不能自主释放；
5. `K` 至少包含一个真实等待、blocked-after-service、blocked-unload、等待运输或等待硬预约兑现的未完成工件。

在 `IMS-RAS^CW` 和 `CORE_THEOREMS_AND_PROOFS.md` 的 CW 假设下，容量介导全局操作死锁等价于存在覆盖所有未完成活动的封闭阻塞核。一般操作死锁、软预约、永久非资源 guard、外部同步缺失或 calendar-empty terminal block 仍需单独处理。

## 10. 简单环的受限地位

状态：反例候选/待实例化。

普通资源请求环只在以下受限子类中可作为候选充分判据：

- 每种资源单实例；
- 每个阻塞工件恰持有一个关键资源并请求一个关键资源；
- 无替代路线、无软预约、无额外残余容量；
- 闭包确定且无优先级副作用。

多容量资源、AGV/预约拆分、缓冲残余容量和替代后继都会击穿“有环即死锁”。
