# IMS-RAS 形式语义

本文档给出首篇论文使用的候选语义。除非显式标为文献基线，所有跨模型命题均为拟证明。

## 1. 模型对象

状态：定义。

一个有限批 `IMS-RAS` 模型是元组

`I = (J, R, cap, route, sem, Z, E_c, E_u, Theta)`。

- `J` 是有限批工件集合，不允许无限外生到达。
- `R = M union B_in union B_out union A union V union R_aux` 是资源集合。
- `cap: R -> Z_+` 给出整数容量。
- `route(j)` 是工件 `j` 的有限阶段序列或有限分支图。
- `sem` 指定 BAS、缓冲、AGV、预约和释放规则。
- `Z` 是零时间事件集合。
- `E_c` 是可控事件，含派工、释放授权、运输选择、预约选择。
- `E_u` 是不可控事件，含加工完成、运输完成；首篇不含设备故障、抢占、动态插单和无限外生到达。
- `Theta` 包含容量、WIP、路线混合、速率和预约规则参数。

## 2. 状态向量

状态：定义。

稳定前状态 `s` 至少包含：

- `stage_s(j)`：每个工件的路线阶段。
- `hold_s(j,r)`：实际物理持有量。
- `res_s(j,r)`：预约 token 持有量。
- `pending_s`：已经触发但尚未完成闭包整理的零时间事件。
- `blocked_s(j)`：工件是否处于 blocked-after-service 或 blocked-unload 等阻塞形态。
- `choice_s(j)`：可选后继集合或已绑定的下一资源/运输/预约选择。

容量守恒分两种 ontology，模型必须二选一并在 `IMSModel` 中显式标注。

第一种是 future-claim ontology：硬预约是对同一物理容量的未来 claim。此时每个资源 `r` 必须满足：

`sum_j hold_s(j,r) + sum_j hard_res_s(j,r) <= cap(r)`。

第二种是 token-resource ontology：预约 token 被建成独立资源 `v in V`，通过映射 `target(v)=r` 关联到物理资源。此时必须分别满足：

`sum_j hold_s(j,r) <= cap(r)` 且 `sum_j res_s(j,v) <= cap(v)`，

并额外证明 token 兑现不会使 `occ_s(r)` 超过 `cap(r)`。

物理资源与预约 token 不能合并记账。软预约允许策略层过度承诺时，必须单独标识 `overbook_s(r)`，不得把软预约视为物理可用容量。

## 3. BAS 与 blocked-unload

状态：定义。

BAS 语义的核心约束：

1. 工件完成加工或运输后，如果下一资源、输出缓冲、AGV 或预约兑现不可用，则进入阻塞状态。
2. `blocked_complete` 与 `blocked_unload` 持续占有其当前机器、AGV 或其它载体，直到卸载或交接事件真正发生。
3. 加工完成是不可控事件；加工完成不等同于资源释放。
4. 资源释放只发生在语义指定的 unload、handoff、leave 或 release 事件之后。

这一点是旧制造岛案例向 IMS-RAS 迁移时的硬边界。把完成事件当作释放事件会消除真实死锁证据，是错误模型。

## 4. AGV 与预约语义

状态：定义。

AGV 相关资源分三层：

- 物理 AGV 占用：工件已装载或 AGV 已承诺执行运输。
- 路段/站台/交接位容量：可建模为资源或容量约束。
- 预约 token：用于提前声明未来占用权。

预约规则分为：

- 硬预约：必须先持有 token 才能进入对应未来占用，token 容量守恒。
- 软预约：允许策略承诺，但兑现时可能竞争失败；必须记录过售风险。
- 无预约：只在实际占用时检查容量。

硬预约最接近资源分配系统；软预约带来状态依赖选择与过售，通常超出经典 S3PR 的直接表达。

## 5. 事件与闭包

状态：定义。

非零时间事件触发后必须立即执行零时间闭包。若 `s --e--> u` 且 `e notin Z`，则可观测后继为 `Cl(u)` 中的稳定状态，而不是 `u` 本身。

一般闭包定义为集合值：

`Cl(s) = {t in S_st : s leadsto_Z* t and no z in Z is enabled at t}`。

只有满足以下额外条件时，才能作为具名语义变体写成确定函数 `kappa(s)`：

- 闭包终止；
- 闭包合流；或
- 规定固定优先级、固定 tie-break、固定排序，且该规则本身进入模型语义。

状态：定义。所有主定理必须在闭包归一化稳定状态 `S_st` 上陈述。若闭包不合流，则状态转换系统从一个触发后状态通向多个稳定后继，控制和概率层必须保留分支。

## 6. 有限状态转换系统

状态：拟证明。

候选构造：

- 状态空间 `S` 由有限 `J`、有限路线、有限容量和有限预约 token 导出。
- 稳定状态 `S_st` 由闭包定义。
- 对 `s,s' in S_st`，若存在非零时间事件 `e` 和中间状态 `u`，使 `fire(s,e)=u` 且 `s' in Cl(u)`，则定义 `s ->e s'`。
- 若 `Cl(u)` 为多值，则 `s ->e s'` 对每个稳定后继 `s'` 都存在。
- 闭包归一化 LTS 记为 `mathcal T=(S_st,s0,A,->,F,D)`。

证明义务：

1. 有限性：所有变量取值有限。
2. 闭包良定义：终止或显式保留非稳定分支/错误状态。
3. 事件守恒：每个事件保持容量守恒与工件路线合法性。
4. 语义忠实：BAS、AGV、预约和 blocked-unload 的占用不被投影丢失。

## 7. CTMC/PH 扩展边界

状态：定义。

`IMS-CTMC` 只在事件保持指数时间或已显式 PH 扩展成有限相位状态时使用 CTMC 方程。一般非指数加工时间不能偷渡进 CTMC；只能作为 DES 仿真或 PH 近似扩展，并在案例中单独标注。

## 8. 首篇排除项

状态：定义。

首篇论文排除：

- 设备故障与维修；
- 抢占；
- 动态插单；
- 无限外生到达；
- 未经 PH 展开的非 Markov 时间；
- 人工干预或在线重规划的非形式化规则。

这些现象可作为后续扩展，不进入首篇主定理假设。
